# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Atlas is a GPLv3 software synth (VST3 on macOS/Windows, plus AU on macOS) forked from Vital. It keeps Vital's DSP engine and adds oscillator types, filter models, effects, effect buses and modulation. Its main design constraint is that **every control must work from the keyboard and be announced by a screen reader** (VoiceOver and Windows screen readers). Vital's graphical interface is gone. The whole UI is one accessible JUCE editor.

## Build and test

Dependencies are git submodules in `third_party/`. CMake refuses to configure without them, so run `git submodule update --init` first. JUCE is `third_party/JUCE8` (8.0.14). CMake applies `third_party/patches/juce8-*.patch` to it at configure time; change JUCE through a patch there, never by committing in the submodule. macOS builds arm64 only.

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel 4
```

Always give `--parallel` a job count. Ninja is not installed, so CMake uses Makefiles, and a bare `--parallel` becomes `make -j` with no limit. Each job can use several GB of RAM (the editor unity file alone is about 19k lines plus JUCE), and an unlimited build will freeze a 16 GB machine. Use 4 jobs. Drop to 2 if the machine is busy.

On Windows CMake uses the Visual Studio 2022 generator. There `--parallel` sets how many projects MSBuild builds at once, and JUCE's `/MP` adds compilers inside each project. `ATLAS_MSVC_COMPILE_JOBS` (default 4) caps those, because an uncapped `/MP` on a many-core machine runs out of memory on the unity files and fails with D8040. Building the plugin together with a test target, use `--parallel 2`. The Windows build also runs MIDL from the Windows SDK to generate the NVDA controller client (see below).

The plugins are written to `build/Atlas_artefacts/Release`. Ship the whole `Atlas.vst3` bundle: a post-build step copies espeak-ng's compiled data (`build/espeak-ng/espeak-ng-data`, which the `data` target builds from the `third_party/espeak-ng` submodule for the Speech oscillator) into the bundle's `Resources/espeak-ng-data`, and the Tape effect's noise recordings (`Factory/Samples/Tape/Vinyl <n>.wav`; the `README.atlas.md` there records their sources, licences and loudness matching) into the bundle's `Resources/Tape` and, on macOS, re-signs the bundle ad hoc. The version the plugins report comes from `project(Atlas VERSION ...)`, and macOS builds target macOS 11.0 (`CMAKE_OSX_DEPLOYMENT_TARGET`).

`installer/macos/build_pkg.sh` packages a finished Release build of `Atlas_VST3` and `Atlas_AU` as `dist/Atlas-<version>-macOS.pkg`, which installs both in `/Library/Audio/Plug-Ins`. `installer/windows/Atlas.iss` is the Inno Setup script for `Atlas-<version>-Windows.exe`, which installs the `Atlas.vst3` folder into `C:\Program Files\Common Files\VST3` (`ISCC.exe /DAppVersion=<version> installer\windows\Atlas.iss` from the repository root; keep its `AppId` fixed so upgrades replace the old install). `.github/workflows/release.yml` builds every push to `dev` on a `macos-26` runner (VST3, AU, .pkg) and a `windows-2022` runner (VST3, .exe) at the same time, and once both succeed a third job replaces the files of the current beta pre-release on the Releases page with all of them (tag `v<version>-<ATLAS_PRERELEASE>`, with `ATLAS_PRERELEASE` set at the top of the workflow; bump it to start the next beta, and write what changed since the beta before in `docs/releases/v<version>-<ATLAS_PRERELEASE>.md`, which the publish job puts at the top of the release notes). A failed build on either platform leaves the release untouched. Platform-specific behaviour is guarded in code (`JUCE_WINDOWS`, `JUCE_MAC`, `vital::kReserveMemoryOnlyWhileUsed`, the editor's key constants), so one `dev` branch builds both. The `build-*` line in `.gitignore` also matches file names, so a new file called `build-something` is silently ignored.

Tests are off by default. Turn them on with `-DATLAS_BUILD_TIMING_TESTS=ON`. That adds about 26 console executables, and each one compiles its own copy of the JUCE modules, so **never build the whole suite** (`cmake --build build` with no `--target`). Build and run only the tests that cover the code you changed:

```sh
cmake --build build --config Release --parallel 4 --target AtlasScreamTests
ctest --test-dir build -C Release -R atlas_scream --output-on-failure
```

To find the right target, grep `CMakeLists.txt` for the `add_test` lines whose names match the feature. Run the full suite (`ctest --test-dir build -C Release --output-on-failure`) only when the user asks for it. CMake marks every test `RUN_SERIAL`, because several tests measure timing and CPU or start their own threads, so ctest never runs them side by side even with `-j`. Every test also gets a timeout (`ATLAS_TEST_TIMEOUT`, 600 s by default), so a hung test fails instead of blocking for ctest's 1500 s default. Tests labelled `cpu` are benchmarks. Leave them out with `-LE cpu` unless you are working on performance. `AtlasPreparedEffectTests --effect-cpu [name]` times each effect alone in a slot. There is no test framework. Each test target is a `juce_add_console_app` with a hand-written `main` that dispatches on a flag (for example `AtlasTimingTests --reverb-filter`). Many `tests/*_tests.h` headers are included into `tests/timing_stability_tests.cpp`. To add a test, add a flag branch in that test's `main` and an `add_test(...)` line in `CMakeLists.txt`. You can run a test binary directly with its flag.

Reference tests compare Atlas against the original code it adapts. They are only added when the opt-in submodules are present: `third_party/aquanode-plugins` (Spectral Lock), `WDL` (EEL2 runs the original JSFX for the JSFX, Reverb filter, Trance Gate and Resonator tests), `nih-plug` (Diopser for Defuse, which also needs `rustc` and Python 3), `openwurli` with `melange` (the OpenWurli oscillator and amp, also with `rustc` and Python 3), and `OpenB3` (the OpenB3 oscillator, Scanner Vibrato and the Analogue Rotary's Whirl model; its C files build with the project's C compiler). Fetch them with `git submodule update --init --checkout <path>` and configure again. `third_party/README.atlas.md` describes each dependency.

## Source layout and build model

- `src/synthesis/`: the DSP, mostly Vital's processor-graph framework (`framework/`, `vital::` namespace, SIMD `poly_float`). A preset must sound the same on Windows (SSE2) and macOS (arm64 NEON), so the SIMD helpers in `poly_utils.h` behave alike on both: `utils::toInt` truncates toward zero everywhere, which the LFO tempo divisions, wavetable frame indices and lookup interpolation rely on. `modules/` holds the per-effect, per-oscillator and per-filter `*_module` processors. A `poly_float` carries two voices' left and right; an effect slot's input has lanes 2-3 equal to lanes 0-1 (the voice handler sums both voices into both pairs) and the host hears only lanes 0-1, so effects process lanes 0-1 once and write (L, R, L, R) rather than run a second engine (Tape still runs both pairs, which seed their dropouts differently). `effects/<name>/` holds standalone engines that a module wraps. `synth_engine/sound_engine.cpp` builds the graph.
- `src/common/`: parameters (`synth_parameters.cpp`), constants and enums (`synth_constants.h`: counts, the `Effect` enum, routing destinations, filter models, file extensions), preset load/save and migration (`load_save.cpp`), `synth_base`, MIDI, tuning, the arpeggiator and the wavetable editor model (`wavetable/`). Large parameter sets live in `*_parameters.inc` files. Each oscillator slot has its own two arpeggiators, and their notes reach the engine on internal MIDI channels 16 + slot, outside the polyphony limit. Every such note takes a voice that plays only its own slot (`ProducersModule::getSourcePlaybackMask`, also while it rings out after the arpeggiator stops) and renders only what that slot reads (`slotsToRender`). A slot that is off gets no arpeggiator notes.
- `src/common/library_layout.{h,cpp}`: the Atlas folder's layout (`atlas::library`). It holds four libraries, Factory, User, Third Party and Community, and each library holds `Banks/<bank>/<category folders>/<preset>` plus one folder per other kind: `Wavetables`, `Multisamples`, `Samples`, `LFO Presets`, `FX Presets` and `Impulse Responses`, each holding packs (folders) and loose files. A bank is a set of presets; the wavetables, samples, LFO and FX presets a bank ships with are a pack named after the bank in those kind folders, and its multisample instruments live once in the library's `Multisamples`. `locate` says where a path sits (library, kind, bank or pack, the folders below as a preset's category); `kindFolderName` is a kind's folder in a library and `archiveFolderName` its folder in a bank archive (`Presets`, `LFOs`, `FX`: archives keep Vital's layout, which the community server also reads). The default User bank (`default_bank` in the config, the bank last saved into, My Bank until then) is `LoadSave::getUserPresetDirectory`; the other `getUser*Directory` are the User library's kind folders. `migrateIfNeeded` (run by `SynthPlugin::createEditor`, only when a host loaded the plugin, `loadedByHost`) moves the two older layouts (kind folders at the library level with banks inside, and the interim `<Library>/<Bank>/<Kind>`) to this one, logs every move in Migration.txt in the Atlas folder and rewrites favourites; `library_layout` in the config (3) says it ran. Before each preset scan in a host, `adoptStrayBanks` files bank-shaped folders dropped at the top of the Atlas folder into Third Party, and the scan unpacks container presets found in banks (`adoptContainerPreset`). Bank archives: `importBankArchive` files an archive into a library (presets as a bank, the rest as packs of its name, instruments into Multisamples unless the library has them by hash) through a hidden staging folder; `writeBankArchive` gathers a bank's presets, its packs and the instruments its presets play. Instruments: `placeInstrument` (called by `SynthBase::writePresetFile` for a preset saved into a bank) refers to an instrument already in the library's Multisamples where it is, reuses one placed before by hash, or places it under `Multisamples/<name>/` with `atlas-multisample.json`; the preset names it in `library_instrument` (its path in Multisamples) and the manager looks there first, then at the path, then in every library by hash. Every Browse menu (`createFileBrowserMenu`) lists library, then packs and folders, then file. LFO presets, FX presets, FX bus presets and instruments come from `SynthEditor::presetFiles` lists, scanned on first use and again after Rescan or a save of that kind; FX presets are listed per effect by their `effect` field (`effectPresetFiles`). Each effect slot in a chain has an FX presets group and each LFO an LFO presets group (Browse, Previous, Next, Import, Save; `addButtonGroup`), loading into the slot's own parameters (`loadEffectPresetIntoSlot`). The bus group has Browse bus FX presets and a Multi-sample slot Browse instruments. Test binaries never reorganise a library: the gates above read `SynthPlugin::loadedByHost`, false for a plugin a test constructs. `docs/library-layout-plan.md` has the design; `AtlasMacroTests --library-layout` tests it in a temporary Atlas folder, `AtlasMultiSampleTests --bank` the instruments, and `AtlasMacroTests --library-migration <folder> <layout> [default bank]` migrates a copy of a real Atlas folder by hand.
- `src/common/community_library.{h,cpp}`: the community preset library (https://atlas.blindproducers.org, the BPAtlasWS Django service) read through its JSON API: page URLs, parsing, where a download lands (`<data>/Community/Banks/<uploader>/<style>/`, the uploader being the bank), SHA-256 and the fetch and download calls, all on a background thread and all working on `file:` URLs so the tests need no network. The editor's preset browser shows it as the Collection facet's Community presets and Community banks rows (`PresetCollection`, `community_index_`, `community_bank_index_`; a bank's archive lands in `<data>/Community/Archives/<uploader>/` and is filed into the Community library under its own name, as Import bank files one into Third Party), with Return downloading and loading or unpacking a row and P playing a row's audio preview: the editor decodes it with a JUCE `AudioFormatReader` read ahead on its own `TimeSliceThread` and plays it from an `AudioTransportSource` that the plugin mixes into its output (`SynthPlugin::setAuditionSource`; the audio thread only ever tries the lock), since a plugin has no audio device of its own. The Preset menu's Share patch and Share bank forms (`showShareForm`, `share_*` controls, laid out like the Save patch form) upload through `uploadPreset`/`uploadBank` (multipart POST with `Authorization: Bearer <token>`); the API token is a password kept in the system's credential store (`src/common/credential_store.{h,cpp}`, outside the unity files so Security.h and `<windows.h>` stay away from JUCE): a generic password in the macOS login keychain for each host app, keyed by its bundle identifier, since the keychain ties an item to the app that saved it and asks for the user's password before another app reads it (so each DAW logs in on its own and nothing ever asks; a host signed ad hoc gets no keychain at all); one generic credential in Windows Credential Manager (`CRED_PERSIST_LOCAL_MACHINE`) for every DAW; and memory alone, until the DAW closes, where the store refuses or there is none. It is never in a file, presets or host state, never logged or said beyond its last four characters. The config holds only which hosts are logged in and as whom (`community_logins`); `hasApiToken` answers the UI without reading the store, `storedApiToken` reads it once a process, and a token an older build left in the config (`community_api_token`) moves into the store. Tests use a `credentials::MemoryStore` (`setCredentialStoreForTesting`, set in `AtlasMacroTests`' `main`); `--credential-store` does a round trip with the real store, keychain dialogs off. The editor's first group is the Toolbar (`toolbar_`, fixed above the scrolling rows so its controls keep focus through rebuilds): the Settings button, Undo and Redo (named after the change, `updateToolbarUndoButtons`, which the timer calls only while `UndoHistory::hasPendingEdits` is false, since describing the history commits a waiting change) and Show preset browser (`EditorMemory::preset_browser_shown`, on by default; off leaves only the summary and Preset menu in Presets). The Settings window (`AtlasSettingsContent`, `showSettings`), which the Settings button opens, holds Plugin info (`SynthEditor::versionText`, with the beta CMake reads from `ATLAS_PRERELEASE` in `.github/workflows/release.yml`), Tuning, MIDI learn mappings (a Remove button each; read when the window opens and after its own changes, since `midiLearnMappings` takes the audio callback's lock), the Accessibility speech settings, the Online community browser group and the Keyboard help (`SynthEditor::keyboardHelpText`). Each group is a `SettingsGroup`, a focus container a screen reader enters but not a keyboard focus container, so Tab still runs through every control; the window's layout components are ignored by accessibility, and every control reports itself accessible offscreen because the groups scroll. In the Online community browser group: `browserShown` hides the community rows and Share items, and the account comes from `/api/v1/me/`. Keep the browser free when unused: nothing is fetched until a community row, Share or Settings asks, and `processBlock` reads one atomic flag (`audition_active_`) unless a preview plays. `AtlasMacroTests --community-library` tests it, uploads against a small HTTP server on 127.0.0.1 inside the test; `--community-probe` lists the live library.
- `src/common/speech/`: the Speech oscillator's off-audio-thread half: espeak-ng (one global state per process, behind a lock), the syllable splitter and `speech::Manager`, which renders each slot's text in the background like the Multi-sample manager loads instruments. The text is slot state saved as `osc_N_speech_text`; the language and variant menus are parameters indexing `src/common/speech_voices.inc`, which is append-only. `src/common/speech/README.atlas.md` describes it.
- `src/plugin/`: the JUCE `AudioProcessor` (`synth_plugin.cpp`) and the accessible editor (`synth_editor.cpp`, about 19k lines). The editor builds rows of labelled controls, menus, the preset browser, the effect slot UI and the modulation UI. `value_bridge.h` and `fx_automation_parameter.h` bridge Vital's values to host parameters.
- `src/interface/look_and_feel/synth_strings.h`: display names and option strings that the editor and screen reader read out.
- `src/plugin/screen_reader_speech.{h,cpp}`: every spoken announcement and the Accessibility settings that filter them (`atlas::speech`). On Windows it speaks and brailles through NVDA's controller interface (`windows_screen_reader.cpp`, built outside the unity file, with the RPC stub MIDL generates from `third_party/nvda_controller`), falls back to a UI Automation notification for other screen readers, and never uses SAPI. On macOS it posts JUCE's VoiceOver announcement. **Never call `AccessibilityHandler::postAnnouncement` directly**: on Windows JUCE speaks it with a SAPI voice. Go through the editor's `post*Announcement` helpers, which check the user's categories and call `atlas::speech::announce`. The keyboard editors (LFO, Trance gate, wavetable) must announce every cursor move, since they have no other spoken feedback. Where JUCE gives NVDA nothing to read, the editor speaks with `postWindowsReadout`, on Windows only since VoiceOver reads these itself: a list's new row (JUCE raises the selection change on the list, not the row; make keyboard lists a `SelectionKeyList` in `synth_editor.h`, as the preset browser tables are) and a toggle's new state (NVDA never speaks a check box's value change; use `SpokenToggleButton`). Open popup menus with `showAccessibleMenuAsync`, which hands NVDA's focus back to the control after the menu closes. Off the Mac, JUCE's Command modifier is Ctrl: test shortcuts with `isCommandChord`/`isControlChord` and name keys with `atlas::keys` (Windows also opens context menus with Shift F10). `AtlasMacroTests --editor-speech` checks the speech. A choice that decides which rows show (an oscillator's Type, a filter's Model, an effect's mode; `isRowSwitchingChoice`) rebuilds the rows when it changes. On Windows that rebuild keeps the focused choice's row and the groups around it (`keepFocusedSwitchingRow`), so NVDA reads only the new value instead of every group again. Create section headers with `makeSectionHeader` and rows with `createAccessibleParameterRow`, which hand the kept ones back. The editor's section and preset browser filters live per plugin instance in `SynthPlugin::EditorMemory`; never put editor state in file-scope variables, since a host loads every instance into one process.

**Unity builds:** most `.cpp` files are not compiled on their own. They are `#include`d from `src/unity_build/{common,synthesis,plugin}.cpp`. `synthesis.cpp` is built with `-ffast-math` (`/fp:fast` on MSVC) in Release. When you add a `.cpp`, add it to the right unity file. Code that needs strict IEEE or double-precision behaviour must be listed directly in `target_sources(Atlas ...)` in `CMakeLists.txt` so that it stays out of the fast-math unit. This applies to the spectral, analogue, resonator, Scream, Defuse, tape, filter-table and Maim code, and the comments there explain why for each. The vendored Braids sources (`src/synthesis/effects/braids`) are listed there too, built with `TEST` and `-fwrapv` so stmlib's macros stay out of the unity files. The Maim effect's codecs are separate C targets: Maim's circuit-bent LAME and BladeEnc and libgsm from `third_party/maim` and `third_party/gsm` (reached only through the wrapper headers in `third_party/maim/include`, since their `config.h` and `common.h` would clash with Atlas's), and Opus from the `third_party/opus` submodule, built by its own CMake. `src/synthesis/effects/maim/README.atlas.md` describes the port. `defuse_module.cpp` also disables FMA contraction. MSVC 19.44 with `/fp:fast` compiles `x + (1.0f & poly_float::equal(a, b))` as `x - (a == b)`, which is NaN in every lane where `a == b`. Clang gets it right, so this breaks only on Windows. In the synthesis code, combine comparison masks with `|`, `&` and `~`, and turn the result into 1.0/0.0 with `1.0f &` once at the end. Never add a `1.0f & mask` to a value.

Include paths are flat: the code uses `#include "foo.h"` across directories through `target_include_directories`. Each test target repeats that include list.

**Memory on Windows:** buffers left uninitialised so that untouched pages cost nothing do cost something on Windows: there they still count against the system's commit limit (Task Manager's commit size), which is what fails when it runs out. And Windows' heap zeroes every `calloc` block under about half a megabyte by hand, making it resident, so zero-filled buffers go through `allocateZeroed` (`zeroed_buffer.h`), which takes blocks of 64 KB or more straight from `VirtualAlloc` there. Anything multiplied by the 17 voice copies or the 3,108 effect shells should be allocated only while it is used. On Windows (`vital::kReserveMemoryOnlyWhileUsed`, in `framework/common.h`) the voice filters' Reverb model holds its delay memory only while selected (`SynthVoiceHandler::updateReverbMemory`; `SynthBase::valueChanged` reserves it before the model changes, and a realtime block that meets it without memory passes audio through and asks for it), a parked effect shell has no dry history, and a latency compensation line (`LatencyCompensatedSum`) gets its history the first time it needs a delay. macOS, where untouched pages cost nothing, reserves all three up front, so switching in realtime never runs a block dry or undelayed. `AtlasPreparedEffectTests --construction` prints the Windows commit after prepareToPlay, and with `ATLAS_LARGE_ALLOCATION_KIB=64` lists the largest allocations by size; `--editor-memory` reports the private working set and commit at each stage.

## Adding or changing an effect, filter or parameter

One feature touches many files. To find all of them, trace an existing effect. For example, `grep -rl TremoloPan src CMakeLists.txt` lists:
- `synth_constants.h` (the `Effect` enum)
- `synth_parameters.cpp` / `*.inc` (parameter definitions)
- `synth_strings.h` (names)
- `reorderable_effect_chain.{h,cpp}` (creating the slot)
- the module files
- `unity_build/synthesis.cpp` or `CMakeLists.txt`
- `synth_plugin.cpp` and `synth_editor.cpp` (host parameters and UI)

Every control must get a label, a value readout (levels as percentages) and keyboard access in the editor. Effect presets live in `Factory/FX/<group>/*.atf`/`.atfx`.

Saved state records `synth_version` and `engine_behavior_version` (`kEngineBehaviorVersion`). Old patches are migrated in `LoadSave::updateFromOldVersion`. When a change alters how existing presets sound or load, add a migration step there rather than changing the defaults. Atlas extensions are `.atp` (preset), `.att` (wavetable), `.ats` (LFO), `.atb` (bank) and `.atf` (FX), and it still reads Vital's `.vital*` formats. An `.atp` is plain JSON unless a Multi-sample oscillator has an SFZ, DecentSampler or SF2 instrument. Then it is a zip with `preset.json` first, followed by the instrument files. Read preset text through `multisample::container::readPresetText`, never as a raw file. `src/common/multisample/README.atlas.md` describes the format, the instrument cache and SFZ, DecentSampler and SF2 coverage.

Code adapted from other projects has a `README.atlas.md` next to it (for example `src/synthesis/effects/spectral_lock/`) that records where it came from, what changed and what the oracle test checks. Keep these files and `NOTICE` up to date when you adapt third-party code.
